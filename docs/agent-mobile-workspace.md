# Pi Agent 移动端工作区

## 目标

Pi Agent 在手机端不再尝试调用 shell。Agent 的文件能力通过应用内的逻辑工作区提供，所有传给模型的路径都是相对于工作区根目录的路径，原生 `file://` 或 Android `content://` URI 永远不会进入模型上下文。

## 工具契约

| 工具        | 能力                                                                                 | 默认策略                 |
| ----------- | ------------------------------------------------------------------------------------ | ------------------------ |
| `read`      | UTF-8 文本读取、按行分页、50 KiB 输出上限                                            | 自动允许                 |
| `write`     | 新建或完整重写文本文件，1 MiB 上限                                                   | 首次变更需确认           |
| `edit`      | 唯一精确文本替换，支持多处非重叠编辑                                                 | 首次变更需确认           |
| `workspace` | `pwd`、`list`、`tree`、`stat`、`search`、`mkdir`、`copy`、`move`、`trash`、`restore` | 查询自动允许；变更需确认 |

`bash` 不会被伪装成移动端工具。系统提示明确告知 Agent：没有进程、npm、Python、Git、编译器或测试运行器。原有系统、Android、MCP 和计算工具仍可按模型能力使用，但审批门只拦截上述四个移动工作区工具。

## 存储与安全

- 默认工作区：`Paths.document/AgentWorkspaces/<workspaceId>/root`。
- 工作区元数据、话题绑定和文件操作审计写入 SQLite；文件内容不写入审计表。
- 写入前对不超过 1 MiB 的旧文件创建本地快照；删除进入回收站（私有沙盒使用应用目录，外部目录使用隐藏的 `.cherry-agent-trash`），并通过应用私有 manifest 保留恢复令牌。
- 路径策略拒绝 URI、绝对路径、Windows 盘符、`..` 穿越、控制字符和 Agent 内部目录。
- `read`、搜索和工具结果只返回逻辑路径；快照原生 URI 只保存在本地审计数据中。
- 文本读取可能随模型请求离开设备，应用 UI 应在后续版本补充隐私提示/设置。

## 外部文件夹

聊天输入栏的工作区按钮可以调用系统文件夹选择器：

- Android 使用 SAF `content://` 目录引用，并在数据库中保存引用。
- iOS 使用当前 Expo 能力提供的会话级目录授权；应用重启后需要重新选择。

外部目录采用同一套相对路径、大小限制和审批策略。跨 provider 的移动/删除使用复制后删除的兼容路径；若 provider 不支持，操作会失败且不会伪造成功。

## 明确不支持

移动端没有通用 shell，因此不能在本地执行 `npm install`、脚本、Git、编译或测试。需要这些能力时应使用桌面/服务器 Agent，再通过应用的文件传输能力交换结果。
