# Pi Agent 移动端工作区

## 目标

Pi Agent 在手机端不再尝试调用 shell。Agent 的文件能力通过应用内的逻辑工作区提供，所有传给模型的路径都是相对于工作区根目录的路径，原生 `file://` 或 Android `content://` URI 永远不会进入模型上下文。

## 运行时挂载

Agent 默认使用应用私有运行时，而不是一个需要用户选择和管理的“工作区文件夹”：

- `inputs/`：本轮与历史消息附件，只读且不复制原文件；
- `state/`：Topic 级持久状态，裸路径默认解析到这里；
- `scratch/`：本轮临时文件与附件派生数据；
- `outputs/`：准备交付用户的文件；
- `legacy/`：旧工作区的只读兼容挂载（存在时）。

用户通过输入框附件把文件交给 Agent；Agent 通过 `publish_file` 或成功运行的自动发布把 `outputs/` 文件放进消息流，用户可从消息中打开或分享。应用不需要把内部状态和临时目录暴露成用户设置。

附件的增量处理协议见 [Pi Agent 的 Agentic Attachment 管线](./agentic-attachments.md)。

## 工具契约

| 工具           | 能力                                                                                 | 默认策略                 |
| -------------- | ------------------------------------------------------------------------------------ | ------------------------ |
| `read`         | UTF-8 文本读取、按行分页、50 KiB 输出上限                                            | 自动允许                 |
| `write`        | 新建或完整重写私有运行时文本文件                                                     | 首次变更需确认           |
| `edit`         | 唯一精确文本替换，支持多处非重叠编辑                                                 | 首次变更需确认           |
| `workspace`    | `pwd`、`list`、`tree`、`stat`、`search`、`mkdir`、`copy`、`move`、`trash`、`restore` | 查询自动允许；变更需确认 |
| `bash`         | 进程内的安全命令适配器，只提供文件查看、查找和统计的允许列表                         | 不启动 OS shell          |
| `publish_file` | 把 `outputs/` 中的完成文件发布到消息流                                               | 仅允许输出挂载           |

`bash` 保留 Pi 熟悉的工具名，但它是进程内允许列表适配器，不是 OS shell。系统提示明确告知 Agent：没有进程、npm、Python、Git、编译器或任意可执行文件。

## 存储与安全

- Topic 状态：`Paths.document/AgentRuntime/topics/<topic-key>/state`；运行缓存位于 `Paths.cache/AgentRuntime/runs/<run-id>`。
- 工作区元数据、话题绑定和文件操作审计写入 SQLite；文件内容不写入审计表。
- 写入前对不超过 1 MiB 的旧文件创建本地快照；删除进入回收站（私有沙盒使用应用目录，外部目录使用隐藏的 `.cherry-agent-trash`），并通过应用私有 manifest 保留恢复令牌。
- 路径策略拒绝 URI、绝对路径、Windows 盘符、`..` 穿越、控制字符和 Agent 内部目录。
- `read`、搜索和工具结果只返回逻辑路径；快照原生 URI 只保存在本地审计数据中。
- 文本读取可能随模型请求离开设备，应用 UI 应在后续版本补充隐私提示/设置。

## 明确不支持

移动端没有通用 shell，因此不能在本地执行 `npm install`、脚本、Git、编译或测试。需要这些能力时应使用桌面/服务器 Agent，再通过应用的文件传输能力交换结果。
